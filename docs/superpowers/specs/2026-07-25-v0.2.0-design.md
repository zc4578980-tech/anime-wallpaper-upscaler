# Anime Wallpaper Upscaler v0.2.0 Design

Date: 2026-07-25
Status: Scope approved; written specification awaiting review

## Product Positioning

Anime Wallpaper Upscaler is a Windows-focused integration and workflow wrapper built on
Real-ESRGAN, `realesrgan-ncnn-vulkan`, and ncnn. It does not claim an original
super-resolution algorithm, model, or inference engine.

Its independent value is a simple wallpaper workflow for ordinary Windows users:

- preserve the complete source composition by default;
- adapt output to the physical desktop resolution;
- fill aspect-ratio differences with a blurred background;
- process individual images or folders;
- generate comparison images automatically; and
- install and run the upstream dependency without manual path configuration.

The repository remains public but is not promoted while v0.2.0 is under development.
v0.2.0 will be the first formal GitHub Release.

## Goals

1. Make first-time setup a single PowerShell workflow without administrator privileges.
2. Install the repository as a Codex agent skill and configure the official Windows NCNN/Vulkan runtime.
3. Let ordinary users process files or folders by dragging them onto a shortcut.
4. Preserve the existing command-line workflow and manual controls.
5. Detect the primary display's physical resolution and available Vulkan GPUs.
6. Produce actionable remediation for missing Python, models, Vulkan support, and network access.
7. Keep upstream binaries and models out of Git while preserving source and license notices.
8. Do not formally release until a conservative, multi-channel launch forecast supports at
   least 30 Stars in the first 30 days without depending on algorithmic Bilibili distribution.

## Non-Goals

- A complex GUI.
- A custom or rebranded super-resolution engine.
- Generative redraw, inpainting, or diffusion-based alteration.
- Bundling upstream executable or model binaries in this repository.
- A self-contained PyInstaller or native application executable in v0.2.0.
- macOS or Linux support in v0.2.0.
- Paid boosts, artificial Stars, bulk unsolicited promotion, or a viral-traffic assumption.

## Supported Environment

- Windows 10 or 11, x64.
- PowerShell 5.1 or newer.
- Python 3.10 or newer.
- A GPU and driver with working Vulkan support.

Python remains a documented prerequisite. The installer detects a missing or unsupported
Python installation and provides the official download link and PATH repair instructions.

## Architecture

The solution has three layers:

1. **PowerShell bootstrap and launcher**
   - detects prerequisites;
   - creates a project-local virtual environment;
   - installs Python requirements;
   - displays upstream source and license notices;
   - downloads, verifies, and extracts the official Real-ESRGAN Windows bundle;
   - registers the repository as a Codex skill; and
   - creates the drag-and-drop shortcut.
2. **Python workflow package**
   - parses CLI input;
   - discovers files and validates options;
   - detects the primary physical display mode;
   - probes the upstream executable for Vulkan devices;
   - runs Real-ESRGAN;
   - builds wallpaper and comparison outputs; and
   - reports per-file and batch results.
3. **Official upstream runtime**
   - `realesrgan-ncnn-vulkan.exe` performs model inference through ncnn and Vulkan;
   - `.param` and `.bin` files provide the upstream network definitions and weights; and
   - upstream licenses and README files remain alongside the downloaded runtime.

The existing `scripts/upscale_wallpaper.py` path remains a compatible entry point. Its
implementation may delegate to focused modules so detection, inference, imaging, and batch
logic can be tested independently.

## Upstream Dependency Setup

The installer uses the complete official Windows bundle published from the
`xinntao/Real-ESRGAN` repository. The standalone Windows asset from
`xinntao/Real-ESRGAN-ncnn-vulkan` v0.2.0 is not sufficient by itself because it does not
contain the required model files.

The dependency manifest records:

- the upstream repository and release page;
- the pinned asset URL and expected byte size;
- a SHA-256 digest verified from a fresh complete download; and
- the upstream license and attribution text shown before download.

Downloads go to a temporary partial file. Extraction occurs only after size and SHA-256
verification. The final directory is replaced atomically only after the executable, selected
models, and upstream license files pass validation. Interrupted or invalid downloads never
create a successful installation marker.

The default runtime location is the repository's ignored `tools/` directory. `--tool-dir`
and `REALESRGAN_TOOL_DIR` remain supported for advanced or existing installations.

## Agent Skill Installation

`setup.ps1` offers to register the repository at
`%USERPROFILE%\.codex\skills\anime-wallpaper-upscale`. On supported Windows systems it uses
a directory junction to the checked-out repository so the skill and application do not drift
into separate copies. An existing non-matching skill installation is never overwritten
without an explicit confirmation.

The standalone workflow remains usable when Codex is not installed; skill registration is a
convenience, not a runtime requirement.

## User Workflow

### First Run

1. Download or clone the repository.
2. Run `setup.ps1`.
3. Review the upstream source and license notice and approve the download.
4. Let the installer validate Python, create `.venv`, install requirements, configure the
   upstream runtime, register the skill when available, and create the shortcut.
5. Receive a success summary containing the installed paths and a smoke-test result.

### Daily Use

- Drag one image, several images, or one folder onto the shortcut.
- When the shortcut is opened without dropped paths, show a native Windows file picker.
- Prompt once for scale: `2`, `3`, or `4`; pressing Enter selects the recommended `4`.
- Detect the primary physical display resolution.
- Use ncnn automatic GPU selection unless the user supplied a GPU ID.
- Process each image and show `[current/total]`, filename, target, scale, and result.
- Open the output directory after a successful interactive run.

Folder processing is non-recursive by default. `--recursive` includes subdirectories while
always excluding the output directory.

## CLI Contract

The existing options remain supported. v0.2.0 adds or formalizes:

- repeatable `--input PATH`, where each path may be an image or directory;
- `--recursive` for folder traversal;
- `--scale {2,3,4}`, default `4`;
- `--target auto|WIDTHxHEIGHT`, default `auto`;
- `--gpu auto|ID`, default `auto`;
- `--tool-dir PATH` and `REALESRGAN_TOOL_DIR` override support;
- `--no-compare` and `--no-upscaled-source` for storage-conscious batch runs; and
- `--no-open-output` for non-interactive automation.

Manual `--mode`, `--model`, `--out-dir`, `--x-bias`, and `--y-bias` controls remain.
Invalid model and scale combinations fail before processing starts.

## Output Policy

The default output directory is `Wallpaper Upscaler Output` beside the input image or inside
the selected input folder. `--out-dir` overrides it.

For each successful image, the default outputs are:

- the Real-ESRGAN source upscale, named with the selected scale;
- the target-size wallpaper, named with target, mode, and scale; and
- the comparison image.

Names are deterministic and do not let 2x, 3x, and 4x runs overwrite each other. The default
wallpaper mode remains `preserve`; crop-to-fill requires explicit `cover` mode.

## Detection

Display detection uses the Windows physical display mode rather than DPI-scaled logical
coordinates. It selects the primary display and reports the chosen `WIDTHxHEIGHT`. Detection
failure produces a visible warning and falls back to `2560x1600`; `--target` always wins.

GPU probing captures the verbose device list printed by `realesrgan-ncnn-vulkan.exe`. The
default remains the upstream `auto` selection. `--gpu ID` passes an explicit device to the
upstream executable after validating that the ID was detected.

## Error Handling

Errors use a short headline, the failed path or command, and a concrete repair action.

- Missing Python: state the minimum version and provide official installation and PATH steps.
- Network failure: preserve retryable state and print the official URL and manual destination.
- Size or digest mismatch: reject and remove the corrupt partial download.
- Missing executable or model: identify each file and direct the user to rerun `setup.ps1`.
- Vulkan failure: list detected adapters and link to NVIDIA, AMD, and Intel driver pages.
- Display detection failure: warn about the fallback and document `--target`.
- Image decode failure: identify the unsupported or damaged file.
- Upstream non-zero exit: retain concise upstream diagnostics and map common failures to fixes.

Single-image failure returns a non-zero exit code. Batch mode isolates failures, continues with
remaining files, and exits non-zero after printing success, skipped, and failed counts. It
writes a short text log in the output directory. The workflow never silently substitutes a
non-AI resize when Real-ESRGAN is unavailable.

## Documentation And Rights

README adds a section titled "How This Differs from Official Real-ESRGAN". It states that the
project is an integration wrapper and attributes Real-ESRGAN, `realesrgan-ncnn-vulkan`, ncnn,
and their upstream authors and licenses.

The current demonstration image remains by the user's decision. README states that the
underlying artwork belongs to its respective rights holder, is used only for technical
demonstration, is not claimed by this project, may be removed on rights-holder request, and is
excluded from the repository's MIT license.

## Verification

Automated and deterministic checks cover:

- PowerShell parser validation;
- Python compilation and CLI help;
- option parsing for scales 2, 3, and 4;
- file, repeated-file, folder, and recursive discovery;
- output naming and output-directory exclusion;
- physical display detection with mocked Windows API results;
- GPU probe parsing and manual ID validation;
- missing Python, executable, models, input, and Vulkan diagnostics;
- simulated network failure, truncated download, and digest mismatch;
- batch continuation and final non-zero status after partial failure; and
- output image dimensions and non-blank pixel content.

Release validation also includes:

- a real installer run using the official archive;
- `--help` from the installed environment;
- a missing-dependency run;
- physical display detection of `2560x1600` on the target system; and
- real 2x, 3x, and 4x small-image runs on the RTX 5070 Ti, checking all expected outputs.

## Launch Readiness And 30-Star Floor

The first-30-day objective is at least 30 GitHub Stars. This is the pessimistic planning
floor for deciding whether the project is ready to announce, not a claim that engineering
can force external users to Star the repository.

The conservative model uses a 3% qualified-visitor-to-Star conversion rate. Before formal
release, the launch plan must identify at least 1,000 qualified repository visits across
independent sources without double-counting. The evidence record states the source, expected
qualified visits, basis for the estimate, and whether placement is confirmed.

The plan must not count:

- Bilibili homepage or recommendation-algorithm traffic;
- paid traffic or paid Star acquisition;
- unconfirmed directory, newsletter, or influencer placement; or
- generic impressions that are unlikely to reach the GitHub repository.

Bilibili may still contribute through search, direct links, profile traffic, and an evergreen
tutorial, but the 30-Star floor must remain supported when that contribution is removed.

The lightweight launch package includes:

- `README.md` and `README.zh-CN.md` with the same factual positioning;
- a first-viewport before/after proof focused on complete-composition wallpaper output;
- an original-to-raw-upscale-to-finished-wallpaper comparison;
- a 60-90 second reusable demonstration and still-image fallback;
- accurate GitHub description, topics, social preview, release notes, and searchable keywords;
- channel-specific, non-spammy introduction drafts for relevant open-source, Windows, anime
  wallpaper, Real-ESRGAN, and agent-skill communities; and
- a day 1, 3, 7, 14, and 30 measurement sheet using GitHub traffic and referrer data.

If the pessimistic forecast remains below 30 Stars, improvement stays lightweight and follows
this order: reduce setup friction, strengthen visual proof, improve bilingual discovery copy,
add a missing targeted channel, and validate the assumptions with a small pre-release test.
A complex GUI, custom inference engine, or unrelated feature expansion is not justified only
to raise the forecast.

## Acceptance Criteria

v0.2.0 is ready when a fresh Windows user with Python 3.10+ can run `setup.ps1`, review and
install the official dependency, and process a dropped image or folder without manually
editing paths or environment variables. All documented failure paths must identify a repair,
all required verification must pass, upstream attribution must remain prominent, and no
upstream executable or model file may be tracked by Git. Formal release is additionally
blocked until the documented pessimistic launch forecast supports at least 30 Stars in the
first 30 days without Bilibili recommendation traffic.
